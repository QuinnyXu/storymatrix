# 转换指南：把现有工作簿整理成「故事数据库」模板

> 给作者，或替作者做转换的工具（如 Claude）。字段的完整定义见 `字段说明.md`（英文版 `field-reference_en.md`），由 `schema/storydb.schema.json` 生成，两者永远一致。
> 下面的例子都来自虚构的示例小说《星河旅店》（`示例_星河旅店.xlsx`）。
> 转换时**另存一个新文件**，不要覆盖原工作簿。

## 1. 模板的思路（像一个小型关系数据库）

| 表 | 一行是什么 | 用 ID 引用 |
|---|---|---|
| 人物 * | 一个人物 | — |
| 事件 * | 一个事件（时间线上的一个点或一段） | 涉及人物ID → 人物；地点ID → 地点；章节ID → 章节 |
| 出场 | 「某人在某事件里做什么、在哪里」 | 事件ID、人物ID、地点ID |
| 行踪 | 某人在一段时间里待在哪里 | 人物ID、地点ID |
| 关系 | 一对人物的关系 | 人物A_ID、人物B_ID |
| 地点 | 一个地点（可有上级地点） | 上级地点ID → 地点 |
| 章节 / 场景 / 伏笔 / 知情台账 / 节日 / 设置 | 见字段说明 | |

规则只有几条：

1. 每张表第一列是 ID（C01、T01、L01、CH01……）。ID 给出后不改、不复用；作废的行把「状态」改成「弃」，不删。
2. 表名、列名按名字识别，列的顺序随意，可以加自己的列（仪表盘会原样显示）。别名也认，例如「时间线」=「事件」、「层标」=「状态」、「生日」=「出生日期」、「时段」=「时间说明」。
3. 一格里多个 ID 用顿号：`C01、C02`。
4. 日期可以写 `2031-07-11` / `2031-07` / `2031` / `2031 春` / `2031 春节`（查「节日」表）/ `约 1850` / `前722`，也可以是 Excel 日期。只知道年份就只写年份，不要编一个具体日子；需要时再加「精度」列。
5. 只想记「谁在场」时，填「事件.涉及人物ID」就够了；要记每个人做了什么、各自在哪里，再用「出场」表。

转完以后的自检：`node tools/storydb.mjs check 新文件.xlsx`，或者把文件拖进仪表盘看「检查」页。

## 2. 已经是「ID + 引用」结构的工作簿：通常直接能用

如果原表已经是每张表一个 ID 列、别的表用 ID 引用（例如「时间线」里有「涉及人物ID：C01、C02」），仪表盘一般能通过别名直接读，**不需要转换**，也不用改列名。先把文件拖进仪表盘看「概览 → 工作簿识别情况」：

- 「找到「时间线」，识别 9 列」之类：说明这张表已对上模板里的「事件」。
- 「其他列：口头禅、成长弧……」：模板里没有的列，会原样显示在人物档案、事件详情和关系提示里。
- 「没有」：这张表模板里有、你的工作簿里没有；可选的表缺了没关系。

再看「检查」页：常见的是 ID 写错（比如章节ID 写了「番外」，而「章节」表里那一章的 ID 是 `EX01`），按提示改即可。`【缺】`、`待定` 写在 ID 格里会被当成「还没定」，不算错误。

想让图更好看，可以选做（都只是加列 / 加表，不改已有内容）：

| 想要 | 怎么做 |
|---|---|
| 关系图按阵营上色 | 「人物」加一列「分组」（如 林家、周家、港务队）；有「阵营」「家族」「所属机构」列的话也认 |
| 指定主要人物 | 「人物」加一列「主要人物」填 是 / 否；不加的话按出场次数自动选 8 位 |
| 关系有方向（暗恋、单方面施压） | 「关系」加「方向」（双向 / A→B）和「强度」（1–3） |
| 时间线上看到每个人各自在哪 | 给事件补「地点ID」，或加一张「出场」表写各自的地点和行动 |
| 一段长时间的停留显示成色条 | 加一张「行踪」表，例如：C02、2031-03-01、2031-05-31、L05（周屿回省城） |

## 3. 「一列一个人物」的宽表：需要转换

很多作者最初的时间线是这样的宽表：一行一个时间点，一列一个人物，格子里写这个人在做什么。

| 公历年 | 月 | 日 | 时段 | 地点（林晚） | 林晚 | 周屿 | 阿婆 | 状态 | 备注 |
|---|---|---|---|---|---|---|---|---|---|
| 2030 | 9 | 1 | | 星河旅店 | 擦桌子，看见门口站着一个湿透的人 | 推门问还有没有房间 | | 已定 | |
| 2031 | 春节 | | | 星河旅店 | 年夜饭 | 第一次包饺子 | 【省城】住院 | 已定 | |
| | | | 年份待定 | | | | | 待定 | 阿婆年轻时的事 |

转换就是把它拆成长表：

**人物**（来自原来的人物表或宽表的表头）

| 新列 | 来自 |
|---|---|
| 人物ID | 新编号 C01、C02……（按原顺序） |
| 姓名 | 全名 |
| 简称 | 宽表表头里的短名字——时间线和图上显示它 |
| 出生日期 | 出生年-出生月-出生日；月日不确定就只写年份 |
| 其他 | 物种、身份、英文名、简介、备注照搬；可以新增「主要人物」「分组」 |

**地点**：把「地点」列里出现过的地名去重，各给一个 L 编号；小地方的「上级地点ID」设为它所在的大地方（星河旅店 → 星河镇）；「区域」可填 城内 / 城外 这样的大分组。像「海边 / 星河镇」这样的组合，拆成两个地点，按事件实际发生地选一个。

**事件**：宽表的每一行 → 一个事件（有好几张时间线表的话，可以用不同前缀，如 前传 B01…、正文 T01…）。

| 新列 | 来自 |
|---|---|
| 日期 | 年 + 月 + 日。月是节日名时写成 `2031 春节`；月日都空就只写年份 |
| 时间说明 | 时段 |
| 事件 | 一句话标题（原表通常没有，需要概括；拿不准时用主视角人物那一格的前半句，状态标「议」） |
| 地点ID | 该行发生地 |
| 类别 | 例如 前传 / 正文 |
| 状态 | 原「状态」。想保留 已定/提议/待定 这样的词，就在「设置」里把「状态取值」写成 `已定、提议、待定`，「已定状态」写成 `已定`，「未定标记」写成 `提议、待定` |
| 备注 | 备注 |
| 其他列 | 原表里本书特有的列（比如某个比赛的冠军）照搬成同名的一列，模板允许加列 |

**出场**：每个非空的人物格 → 一行（事件ID、人物ID、行动 = 格子内容）。格子以 `【地点】` 开头的（如上表阿婆的「【省城】住院」），把这个地点填进「地点ID」并从行动里去掉。人物不在事件地点、又没写地点的，「地点ID」留空。

**节日**：如果原表有「节日日期」表（年份 | 春节 | 元宵 | …），可以原样保留，仪表盘也认这种宽格式。

**不需要的**：年龄速查表、按公式算出的日期和年龄列（仪表盘自己算）。

注意：只适用于某一本书的特殊规则（例如「魔法只在满月夜生效」「使节每年只能入京一次」）不在通用检查里。通用检查包括：出生前出场、去世后出场、同日两地、与行踪矛盾、伏笔先回收后埋设等。特殊规则可以照 `src/std/checks.js` 的写法另加一个检查函数。

## 4. 让 Claude 帮你转换时，可以这样说
